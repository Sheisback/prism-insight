## 확인한 문제

1. `weekly_insight_report.py`의 트리거 집계에는 주간 날짜 조건이 없다.
   366/244건과 339/250건은 이번 주 결과라고 해석할 수 없다.
2. 미매수 후 하락/상승 건수는 가상 관찰 결과다. 손실 회피의 인과 증거나
   매수 기준 완화의 근거가 아니다. 같은 종목의 여러 분석 기록도 포함될 수 있다.
3. 기존 매도 평가 함수는 이후 등락이 -1%부터 +3%까지이면 무조건
   “적절한 매도”를 반환한다. 판단 당시 정보·위험·반대 상황은 평가하지 않는다.
4. 직관은 condition/insight 완전 일치로만 중복 처리했다. 동일 코퍼스를 다시
   처리할 때 근거 건수를 더하고 전체 코퍼스 ID를 개별 원칙의 출처로 저장했다.
5. 운영 직관 12/18/78은 같은 추격 진입 위험을 다루면서 category/subcategory가
   각각 다르다. 분류명 일치만으로는 의미 중복을 해결할 수 없다.
6. 신뢰도 93~97%는 모델 추정값이며 검증된 예측 정확도가 아니다.
7. 9월 27일 03시 운영 압축 로그는 refresh에서 9개 추출, 압축 뒤 활성 64개,
   cleanup에서 14개 비활성화, 최종 50개를 기록했다. 기존 cleanup의 개수 제한은
   의미 중복 통합을 대체하지 못한다. 보고서의 신규 2개는 생성 전체 수가 아니라
   이번 주 생성된 것 중 현재 활성인 개수다.

양쪽 모두 `PROSPECTIVE_DATES_LT_20`, `PROSPECTIVE_CANDIDATES_LT_100`,
`CAPTURED_CANDIDATES_LT_100`, `STRATEGY_CLOSED_TRADES_LT_30`이다.
연결된 30일 후보 결과는 0건이며, 관측 이후 표본에서 트리거 우열을 검증할 수 없다.
이 표본은 보고서의 전체 누적 legacy 집계와 다르다. 둘을 대체하거나 합산하지 않는다.

양쪽 후보 ID 연결률·capture는 100%, 미래정보 누수 제외 0건이다.
원장 입력에서 event ID 중복 49건은 도구가 제거했으며 후보 decision 중복은 0건이다.
US는 진입 5건 중 체결 확인 0건(주문 제출 4, 거절 1)이므로 브로커 실현손익은
검증되지 않았다. 이와 별개로 연결된 전략 청산 5건은 유효하게 보존했다.
DGX의 전략 원장 수익률은 -1.5417%로 보고서의 -1.5%와 일치한다.
보고서 가격으로 계산한 매도 이후 변동은 `(236.32 / 232.46 - 1) * 100 = 1.6605%`다.
현재 시세 재조회로 과거 보고서의 가격 시점을 덮어쓰지 않았다.

판정: `CONTINUE_CAPTURE`. 새 전략이나 매수 기준 변경을 제안하지 않는다.

- 운영 배포 후 import/읽기 전용 스모크와 첫 정규 배치를 따로 기록한다.

경고가 남는다(기준선 11건, 현재 10건). 새 테스트의 Ruff 오류는 없다.
LSP 도구는 Python에도 tsc를 실행하므로 Python 타입 검증 증거로 사용하지 않았다.
별도 legacy `tests/test_trading_journal.py`는 로컬 `mcp_agent` 미설치로 수집하지 못했다.
Kakao 소비자 테스트 2개도 로컬 `markdown` 미설치로 실행되지 않았으며 본 변경 범위 밖이다.

PR CI·운영 배포·첫 정규 배치 성공은 아직 미확인이다.

압축 모델에는 입력 기록을 직접 전달하고 SQLite 도구 접근을 제거했다.
모든 저장·통합은 검증된 코드 경계를 거친다. 의미 중복은 LLM 제안과 별도 검토에
의존하므로 불확실하거나 API가 실패하면 기존 원문을 유지하며 다음 실행에서 재시도한다.
정적 분석의 신규 SQL 조합 경고는 고정 SQL과 바인딩으로 해소했다.
시장 필터 후 코퍼스 개수를 제한하고, 통합 시 최초 생성일과 최근 실제 검증일을 보존한다.
