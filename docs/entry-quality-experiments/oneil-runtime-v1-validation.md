# 최초 최대50% 실행 경계 검증

검증일: 2026-09-27. 로컬 구현/검증 보고이며 운영 실행 또는 LIVE 준비 완료 보고가 아니다.

## 사용자 선택 및 완료 범위

사용자가 최초 최대50%를 확정했다. 새 기본군은 `INITIAL_POLICY_50`이며 기존10%
호환군과 캠페인 ID·cohort·원장 설정을 분리했다. 최초 캡처 때 가상50%를 소급
매수하지 않는다.0% 대기→현재 조건과 위험 한도에 맞춰 최대50%→후속 유효 봉에서
80/100% 순서로 기존 평가기를 실행한다. 첫 진입 없이 종료되면 NO_ENTRY다.

완료한 실행 경로:

`원본 캡처 + 현재 보유DB → 실제 시세/국면/거래량 → 현재 gate → 공통 정책 → 원자적 가상 회계`

주요 파일은 `prism_core/oneil_runtime_inputs.py`, `oneil_shadow_runner.py`,
`oneil_runtime.py`, `oneil_live_boundary.py`, `strategy_ledger.py`,
`tools/run_oneil_shadow.py`다. 새 회계·브로커 엔진을 만들지 않고 기존 계산기와
원장을 재사용했다. 실행법과 미완료 항목은 `docs/ONEIL_RUNTIME_ko.md`에 기록했다.

## 통합 및 회귀 검증

- root 정책·입력·원장·실제 보고서/보호 경로·병합된 회귀: **657개 통과**.
- 별도 US 실제 tracking/trend-exit 모듈: **61개 통과**.
- KR/US 공급자 형태·실제 오전/오후 배치·research prefetch: **94개 통과**.
- 별도 US prefetch as-of/실제 분석 코어: **4개 통과**.
- 합계 **816개 소프트웨어 검사**. 거래 표본 수나 성과 증거가 아니다.
- 변경 파일 Ruff/compileall/diff-check 통과. Python 타입 검사기는 제공되지 않았으며
  tsc 기반 LSP 결과를 Python 타입 검증으로 사용하지 않았다. 기존 Pydantic 경고가 있다.

정상 ADD·최초50 상한·위험 축소·후속100·동일봉 중복 방지·CAS 경쟁·재시작·결측·
지연 청산·NO_ENTRY·모드 변경 거부·입력DB 바이트 불변·하드링크 거부를 검증했다.
준비군의 계좌 계산은 기존 정수주 계산기를 사용하며, 미확정/부분체결/예약/미정산/
잘못된 계좌/가상체결/기존 포지션 편입을 거부한다. 이 계산은 주문하지 않는다.

별도 검토에서 찾아 수정한 문제:

1. 직접 mark로 원장 CAS를 우회하던 경로를 차단했다.
2. 시장 자료30행만으로 장기 국면 판정이 달라질 수 있어 GSPC200개 연속 거래일을 요구한다.
3. 여러 종목을 순회할 때 거래량 이력 캐시를 지우지 않도록 종목별 bounded cache를 사용한다.
4. 지연된 청산은 마지막 관찰 시각 대신 실제 회계 변경 시각과 비교한다.
5. exit tape 장애는 증액을 차단하지만 독립 보호를 막지 않는다.
6. 입력 DB의 하드링크를 출력으로 지정하는 것도 초기화 전에 거부한다.
7. 현재 캠페인에 새 보유행을 만들지 않으므로 자기 슬롯을 중복 차감하지 않는다.

검토 결론은 SHADOW 코드 범위 승인이다. LIVE 준비 완료 승인이 아니다.

## 배포·운영·수익성·LIVE 상태

- 최신 origin/main의 트레일링 최고가 수정과 재진입 작업을 정상 병합했다.
  병합 commit `5d46e019`. 다른 세션 작업을 되돌리지 않았다.
- 이번 코드의 원격 CI·서버 배포·운영 flag/cron 변경·첫 예정 SHADOW 실행은 **미실행**이다.
- 원본 캡처와 exit tape에는 여전히 best-effort 누락 가능성이 있다. 새 runner는
  시작 후 중단된 주기를 영속 식별하지만, 실행 자체가 시작되지 않은 시간이나 원본 누락을
  완전 복구하는 수집 시스템은 아니다. 수집 무결성/실체결/전진 성과 입증과 구분한다.
- 기준선은 원래 즉시 진입, 새50군은 현재 조건이 처음 확인된 시점에 진입하므로
  평가 지연도 비교 결과에 포함된다. 순수 비중 변화의 인과효과로 해석하지 않는다.
- 이전 실제 Packet의 paired0 상태를 새50군의 성과로 바꾸지 않았다.50군 수익성 미입증.
- **LIVE 즉시 전환은 미완료**: 최초 주문 대체, 원자적 계좌 소유권, 확인체결 대사,
  주문 예약/복구, 증액·청산 조정, 브로커 전달의6개 연결이 필요하다.
  코드에서 LIVE를 거부하며 계산 성공이나 환경변수로 우회할 수 없다.

다음 작업은 위6개 LIVE 실행 연결을 실제 계좌 경계와 통합하는 것이다. SHADOW 배포와
전진 관측도 별도로 검증해야 한다. 준비가 끝난 뒤 새 캠페인부터 LIVE 승인을 받는다.
