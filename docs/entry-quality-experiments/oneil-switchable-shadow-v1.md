# LIVE 전환 가능한 SHADOW 배포 계약

2026-09-27. 사용자 요청은 최초 최대50% 적응형 전략의 실행 경로를 완성하고
운영 SHADOW로 배포하는 것이다. 실제 LIVE 주문은 이번 승인 범위가 아니다.

## 완료 기준

1. 최초 최대50%→조건부80/100%의 기존 정책을 SHADOW/LIVE 모두 사용한다.
   SHADOW는 모의 주문·체결이고 LIVE는 기존 ExecutionService를 통한 실제 경로다.
   명칭만 LIVE인 stub 또는 영구 NOT_IMPLEMENTED 차단을 완료로 취급하지 않는다.
2. 최초 LIVE 진입은 기존 전액 주문을 대체한다. 성공·대기·거절·예외 모두 기존
   전액 BUY로 내려가지 않는다. 이미 가진 종목/가상 포지션을 실제 보유로 편입하지 않는다.
3. 계좌·종목·캠페인 실행권, 목표 비중, 주문 예약과 멱등 키를 한 트랜잭션에 기록한다.
   정규/기계/보호 경로는 같은 실행 원장을 사용한다. 모드는 캠페인 생성 후 불변이다.
4. exact 주문번호·일자·종목·방향의 실제 누적 체결 수량/금액과 미체결을 조정한다.
   API 실패의 빈 목록, 접수 ACK, 보유수량 차이만으로 체결/취소/FLAT을 확정하지 않는다.
   수수료가 API에 없으면 실제 수수료는 UNKNOWN이다. 등록된 비용 모형을 위험 계산에
   사용하는 것과 실제 비용·PnL 확인은 구분한다.
5. 청산 요청을 먼저 고정해 새 증액을 막고, 진행 중 매수의 취소/체결을 확인한다.
   확인된 소유 수량만 매도한다. 예약 후 재시작/네트워크 UNKNOWN이면 중복 제출하지 않는다.
   보호는 승인 만료/신규매수 중단과 독립적으로 유지한다.
6. 기존 전략 원장 결과는 브로커 거절/잔고 부족과 독립적으로 보존한다. 실제 계좌
   실행 상태는 별도이며 확인 전 실현손익을 주장하지 않는다.
7. 코드·실제 모듈 테스트·필수CI·정상병합 후 clean 서버에 ff-only 배포한다.
   원본 캡처/SHADOW 실행을 활성화하되 기존 LIVE 주문 경로와 승인정보는 바꾸지 않는다.
   서비스 스모크와 최초 예정 주기 완료를 구분해 검증한다.

## 기존 전략과의 적합성

스크리닝·보고서·LLM BUY·기존 결정론적 gate를 통과한 신규 후보만 다룬다.
보고서 sidecar의 proper-base/성장 검토가 추가 연구 조건이다. 기존 후보 선발을
소급 변경하지 않는다. US process_reports의 `_buy_stock_with_position` 이전에
신규 LIVE 분기를 두며, SHADOW에서는 기존 전략/브로커 결과를 바꾸지 않는다.
증액은 같은 캠페인의 예산을 늘리는 것이므로 legacy 피라미딩의 독립 보유행을
추가하지 않는다. 기존 손절·추세 청산 요청은 같은 소유권 경계로 전달한다.

가설·조건·5% 추격 상한·5일 증액 만료·비용/위험 계산·최대 배분은 기존
oneil-adaptive-v1을 유지한다. 완전한 CANSLIM이나 수익성 입증으로 일반화하지 않는다.
전환은 미래 신규 캠페인부터이며, 성과 기준과 명시적 LIVE 승인은 여전히 필요하다.

## 검증

- OFF/SHADOW에서 기존 BUY/SELL/주문/채널 차이0, SHADOW 신규 브로커 호출0.
- LIVE fake adapter로 실제 ExecutionService/IntentStore 경계를 실행하되 네트워크 주문0.
- 최초50 상한/위험축소, 후속 증액, 계좌 분리, 정수주/예산, 정확한 지정가/수량.
- 정규·기계 동시 요청, 증액과 청산 경쟁, 부분체결/취소/UNKNOWN/재시작/계보 오류.
- 실제 공급자 조회와 운영 import/설정/서비스/주기 스모크. 실주문으로 시험하지 않는다.
- 실현 수익성, prospective 기간·표본은 배포 이후 별도로 축적한다.

현재 상태: 실행 연결 구현 중. 이번 목표가 달성되기 전에는 배포 완료/전환 준비
완료라고 보고하지 않는다.
