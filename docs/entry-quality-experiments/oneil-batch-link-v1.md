# 자동 검토와 최초 시나리오 연결

2026-09-27. 기준 코드 `6f67b1af`. 기존 경제 규칙은 변경하지 않는 연구 입력 연결이다.
운영 활성화와 수익성 판정은 별도이며, 이 문서는 배포 증거가 아니다.

## 변경 전 범위와 검증 계약

1. 기존 US 오전/오후 스크리닝·보고서·BUY/SELL·게이트·원본 시나리오를 유지한다.
   보고서 생성에서 이미 확보한 종목 일봉과 실제 분기 재무를 구조화하고,
   명시적으로 켠 경우에만 보고서 단계에서 SPY 비교 자료를 추가 수집한다.
   매수·손절 루프에서 새 네트워크/LLM 호출을 하지 않는다.
2. 가설은 등록된 `oneil-adaptive-v1` 및 `oneil-auto-review-v1` 그대로다.
   새 평가는 보고서/PDF와 분리한 보조 자료이며 기존 점수·프롬프트에 주입하지 않는다.
3. 실제 경계는 `prism-us/cores/data_prefetch.py` → `us_analysis.py` →
   `us_stock_analysis_orchestrator.py`의 보고서 저장 →
   `us_stock_tracking_agent.py:process_reports`의 전략 진입 확정 →
   `observability/scenario_shadow.py`의 원본 동결이다.
   기존 스크리닝/BUY가 허용해도 자동 검토가 거부할 수 있다. 이는 다른 연구군의
   적격성 차이이며 기존 매수를 차단하는 모순된 게이트로 추가하지 않는다.
4. `report:<PDF basename>` 결정 ID, 종목, PDF 원문 hash와 자료 확보 시각을 검증한다.
   전략 진입 후 실제 position ID에 연결하고 브로커 거절과 독립적으로 보존한다.
   같은 보고서의 여러 계정 포지션은 별도 최초본이며, 과거 최초본은 덮어쓰지 않는다.
5. OFF/ON/입력 실패에서 기존 판단·주문·메시지 차이0을 실제 모듈 시험으로 검증한다.
   없는 SPY·기업행사·통화·분기값을 긍정값으로 채우지 않고 MISSING으로 남긴다.
   보고서 불일치·미래 자료·다른 결정 ID·변조·중복 캡처를 반례로 검증한다.
6. 기본 OFF, 기존 보호와 분리, 원장 ingestion/주기 평가/현재 게이트 공급은 별도다.
   활성화하지 않으면 기존 시스템이 기준선이며 수익성이 입증됐다고 부르지 않는다.

## 수익성 비교의 범위

이번 비교기는 기존100% 진입 대비 기존 캡처와 호환되는10% 선진입+적응형 증액의
같은 캠페인 비교를 지원한다. 최초50% 진입 전체 전략이나 새로운 트레일링스탑을
검증한 것으로 일반화하지 않는다. 비교 계약은 `oneil-paired-replay-v1.md`에 분리한다.
과거 당시의 setup·확정봉·동시간 거래량·게이트가 없으면 현재 자료로 복원하지 않는다.
유효한 원장 손익과 새 전략을 재생할 수 있는 입력 완결성은 다른 문제다.
