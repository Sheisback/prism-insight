# 장중 입력 원장 연결 및 동일 조건 비교 v1

등록일: 2026-09-27. 기준 commit `f1de1e9c`. 구현 전에 비교 범위를 고정한다.

## 변경 계약

1. 연구 입력 연결이다. `oneil-adaptive-v1`의 조건·위험 한도·비용·기존 손절은
   변경하지 않는다. 기준선100%와 `COMPATIBILITY_SCOUT_10`을 비교한다.
   최초50% 진입이나 새로운 트레일링 정책의 성과로 일반화하지 않는다.
2. 가설은 확인된 상승에 빠르게 증액하면 실패 진입 손실을 줄이면서 상승 참여를
   유지할 수 있다는 것이다. 확인을 기다리는 비용과 증액 직후 실패를 반례로 둔다.
3. 기존 스크리닝→보고서 sidecar→최초 계획 연결은 기존 계약을 유지한다.
   `observability/scenario_shadow.py`의 최초본, US 정규 보유 검토,
   `tools/hardstop_seller.py`의 보호 완료 이후 관측, committed exit를 별도 원장에
   연결한다. 보호·주문을 위한 새 게이트나 네트워크 호출을 추가하지 않는다.
   숫자만 제공하는 현재가를 거래소 시각이 확인된 fresh quote로 바꾸지 않는다.
   현재 증액 게이트·동시간 거래량이 없으면 MISSING을 기록한다.
4. 같은 최초가격·같은 관측가격·같은 원본 손절 경로·같은 청산으로 sizing만 비교한다.
   편도10/25bps, 최고 기준선 승자 제거, 승자 이익포착90% 기준은 기존 등록을 따른다.
   자료 결측 캠페인은 제외 사실과 분모를 보존하고 수익0으로 대체하지 않는다.
5. 아래 합성 경로는 오류·반례 검사이며 표본 수나 수익성 증거가 아니다.
   실제 기록은 당시 입력이 완전한 경우에만 탐색 비교한다. 새 운영 관측 경계 없이
   prospective 또는 holdout이라고 표시하지 않는다. 규칙 튜닝은 하지 않는다.
6. 기존 운영 유지. 기본OFF 연결, 새 cron·운영 flag 변경·전략 승격 없음.
   입력 누락/충돌/재시작은 명시적으로 기록한다. 안전한 원장 경로만 허용하고
   실패가 기존 매수·손절·청산을 막지 않도록 한다.

## 사전 고정 합성 반례

모든 진입100, 초기 손절90. 별도 명시한 손절100은 기존 시스템이 이미 올렸다고
가정한 공통 입력일 뿐, 신규 트레일링 구현이 아니다.

| 경로 | 장중 가격 / 공통 손절 | 청산 | 검증 질문 |
|---|---|---|---|
| 상승 확인 | 102 / 90 | 120 | 위험 한도 안에서 직접80% 목표가 가능한가 |
| 강한 상승 확인 | 104 / 100 | 120 | 직접100% 확대와 뒤늦은 매입 비용 |
| 손절 유지 상승 | 104 / 90 | 120 | 같은100% 목표도 원래 위험 한도로 제한되는가 |
| 최초 돌파 실패 | 89 / 90 | 89 | 증액 전 실패 손실 완화와 보호 우선 |
| 증액 직후 실패 | 104→99 / 100 | 99 | 증액이 오히려 손실을 키우는 반례 |
| 거래량 미충족 상승 | 104 / 90, 동시간1.0배 | 130 | 수익 종목을 적은 비중으로 보유하는 비용 |
| 추격 상한 초과 | 106 / 90 | 130 | 5% 제한 때문에 놓치는 상승 |
| 현재 게이트 결측 | 104 / 90 | 120 | 비교 불가를 정상 관망 성과로 둔갑시키지 않는가 |

비교기는 기존 평가기와 StrategyLedger를 재사용한다. 독립적인 새 회계·주문 엔진은
만들지 않는다. 현금 재배치·다종목 동시 보유·실제 체결·포트폴리오 MDD는 범위 밖이다.
