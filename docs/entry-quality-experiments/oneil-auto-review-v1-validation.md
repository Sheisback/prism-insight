# 자동 베이스·성장 검토 v1 검증

2026-09-27. 계산 규칙의 기능 검증이며 수익성·운영 승격 검증은 아니다.

## 구현

- `prism_core/oneil_auto_review.py`: 일봉·실제 분기 수치로 고정 규칙을 계산한다.
- `prism_core/oneil_auto_review_output.py`: 계산 결과로 별도 근거표와 검토 JSON을 생성하고
  기존 source-bound setup 어댑터를 재사용한다. 사람의 승인으로 위장하지 않는다.
- `tools/build_oneil_auto_review.py`: 공개 시세2개(대상/SPY)와 대상의 재무 snapshot을
  제한된 읽기 전용 호출로 수집한다. 기존 가격 수집기를 재사용하며 DB·계좌·LLM·주문은 사용하지 않는다.
- 기존 collector는 명시적인 NYSE Arca 코드PCX를 지원하도록 확장했다. SPY를
  거래소 불명으로 버리는 경우를 재현한 뒤 수정했으며, `exchange=None`을 추정 보완하지 않는다.
  기존 frozen cutoff와 과거 artifact는 변경하지 않았다.

## 실제 제공자 자료 스모크

AAPL과 SPY의 일봉, AAPL 실제 분기 diluted EPS/매출을 수집했다.
판단시각2026-09-27T10:12:59.191157Z, 재무 확보시각10:12:59.088401Z다.
발표일이 아니라 **현재 제공자 자료를 확보한 시각**이며 과거 분기말로 소급하지 않았다.

- 플랫 베이스: 검사한5~8주 범위에서 조건 미충족. 각 기간의 깊이·선행 상승과
  실패 사유를 따로 보존했다. 이유의 합집합이 한 기간에서 모두 발생했다는 뜻은 아니다.
- 제공자 표기2026-06-30 vs2025-06-30: EPS2.02/1.57로 성장률 약28.66%,
  매출109,417,000,000/94,036,000,000으로 약16.36%였다.
  매출25% 기준을 충족하지 못해 성장 조건을 통과시키지 않았다.
- 같은61개 관측일(60구간) 가격 성과의 SPY 대비 차이는 약12.43%p였다.
  배당을 포함한 총수익률이나 IBD RS등급·업계 순위가 아니다.
- 결과setup_status=REJECTED, live_ready=false. AAPL 매수/매도 권고나 기업 경쟁력
  전체의 부정 판정이 아니라 이 등록된 부분집합 기준의 계산 결과다.

현재 제공자 자료의 정확성을 SEC 원문과 독립 대조한 것은 아니다. 서로 다른 재무 범위,
통화, 추정치가 명시되면 거부하지만 원본 제공자의 누락/오류까지 해결했다고 주장하지 않는다.

## 재현성과 검증

동일 snapshot에서는 같은 계산서·검토 JSON·setup과 Packet ID를 생성한다.
긍정 fixture는 자동 검토→근거 원문 확인→setup→적응형100% 목표 선택까지 연결했다.
음수 EPS분모·부족한 기간·미완성 주·휴일 누락·split·미래 재무·다른 자료 범위·추정치와
긍정적인 문구만 있는 반례는 통과시키지 않았다.
이 통합시험도 실제 broker 체결이나 실제 수익률의 증거가 아니다.

최종 검증: 관련 회귀 테스트373개와 KR·US 시세/배치 실제 모듈 통합 테스트51개가
통과했다. 변경 Python 파일의 Ruff, compileall 및 git diff --check도 통과했다.
저장된 원본을 두 번 재실행한 Packet ID는 아래 값으로 일치했다.
`9a302199e834cc11e4f550a83a3a0274ce383fe4f0c24d185a386bb5681c768d`
증거는 `.omx/evidence/oneil-auto-review-smoke-20260927.json`에 보존했다.
원격 CI, 배포, 운영 활성화, 첫 예정 배치 실행은 하지 않았다.

## 실행

```bash
python3 tools/build_oneil_auto_review.py --symbol AAPL --calendar NASDAQ \
  --output /absolute/new-review.json
```

`--saved`는 저장된 source와 원래 검토 시각으로 재계산한다. 새 관측으로 세지 않는다.
원본 자료와 구현 파일 hash를 결과물에 남기며 기존 파일을 덮어쓰지 않는다.
실제 거래 후보의 decision_id 연결은 아직 하지 않았고 CLI의 ID는 research 참조다.

다음은 정상 보고서 생성에서 이미 받은 자료를 재사용해 이 검토 결과를 sidecar로 저장하고,
원래 decision/position과 정확히 연결하는 작업이다. 매분 재무·400일 가격을 다시 조회하는
스케줄을 만들지 않는다. 그 뒤에 별도 SHADOW 원장·장중 평가와 연결한다.
