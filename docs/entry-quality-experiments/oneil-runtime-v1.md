# 적응형 SHADOW 실행 경계 v1

2026-09-27. 기존 `oneil-adaptive-v1` 조건은 변경하지 않는다. 이번 요청은 실제
SHADOW 구동과 향후 LIVE 전환 준비이며, 실주문 활성화 승인이 아니다.

## 사전 범위 및 적합성

1. 입력/실행 연결 변경이다. 평가기는 기존 `evaluate_target`, 회계는 StrategyLedger를
   재사용한다. 구현 도중 사용자가 최초 최대50%를 명시적으로 확정했다. 신규 기본값은
   `INITIAL_POLICY_50` / cohort `initial-policy-50-v1`이다. 과거10% 비교는 별도
   `COMPATIBILITY_SCOUT_10`으로 보존하며, 다른 arm의 원장을 새 arm으로 편입하지 않는다.
2. 상승 확인 시 증액한다는 가설과 실패 반례는 기존 사전등록 그대로다. 새 임계값이나
   최근 합성 결과에 맞춘 최적화를 추가하지 않는다. 기존 손절을 넓히지 않는다.
3. 기존 US 스크리닝→보고서 sidecar→최초캡처를 입력으로 쓰고, 별도 runner가 실제
   시세시각/현재 portfolio/결정론적 gate/동시간 거래량을 공급한다. 정규·기계 구분은
   입력 출처이며 같은 평가기를 사용한다. 네트워크 수집을 기존 보호루프에 넣지 않는다.
   `cores/buy_gate.py`의 RR/위험폭 검사를 재사용한다. 이미 가진 종목의 sector 검사는
   기존 US `_check_sector_diversity`의 보유종목 우회를 따르지만 정확한 포지션 확인이 필요하다.
   legacy 피라미딩의 여러 독립 보유행 규칙과 새 단일 캠페인 누적 비중은 다른 정책이다.
   정확히 자기 보유행 하나가 확인된 같은 캠페인은 이미1슬롯을 차지하므로
   `slots_used - 1 < limit`를 적용한다. 새 보유행을 추가하는 legacy 피라미딩의
   `slots_used < limit`를 중복 적용하지 않는다. 한도 자체는 늘리지 않는다.
   시장 입력은 완료된 지수 일봉을 사용하며 진행 중인 당일 일봉을 제외한다.
   기존 배치가 진행 중 일봉을 포함할 때와는 의도적인 확정성 차이가 있다.
4. 기준선100은 원래 적격 진입가격을 보존한다. 신규50군은0% 대기에서 시작하며
   최초의 유효한 현재 입력으로 최대50%를 실제 관측가격에 배분한다. 그 뒤 조건에
   따라80/100%로 확대한다. 기록을 보고 과거 진입시점에50%를 소급 매수하지 않는다.
   따라서 기존 즉시 진입과 주기 평가의 시간 차이도 결과에 포함되며, 순수 비중만의
   효과로 해석하지 않는다. 같은 원본stop·terminal로 비교하며 ledger에 입력과
   결정을 원자적으로 남긴다. 결측과 보호는 독립이다. 원본 가격이 없는 terminal을
   현재 시세로 복원하지 않는다. 소급 생성·합성은 prospective가 아니다.
5. 모드/정책/캠페인 소유권은 불변이다. SHADOW→LIVE는 진행 중 가상 포지션 전환이
   아니라 승인 후 새 캠페인의 실행 경로 선택이어야 한다. 기존 전액 매수 뒤 ADD를
   더 보내는 것은 금지한다. 실패/UNKNOWN/미확인 체결은 실제 계좌 증액을 차단한다.
6. LIVE는 별도 첫 진입 대체 라우터·원자적 계좌 소유권·체결 reconciliation·매도와
   미체결BUY 조정까지 연결/검증해야 한다. 준비 상태에 없는 것을 환경변수만으로
   PASS 처리하지 않는다. 기존 원장/브로커/보호를 보존하며 실제 활성화는 하지 않는다.

## 검증 계약

- 실제 생산자/현재입력/정책/원장 통합: 정상 ADD와 거절·MISSING 양방향.
- 동일봉 정규/기계 경쟁, CAS, 중복재시도, 프로세스 재시작 후 추가 leg 중복0.
- quote 미래/오래됨, 잘못된 종목·계좌·결정 연결, portfolio/market 결측 차단.
- 기존 원장 및 계좌DB는 읽기 전용. 원본 captures/tape와 새 실행원장은 분리한다.
- 현재 보호가격 이탈은 증액자료 누락과 무관하게 가상청산 우선. 기존 실물보호 불변.
- LIVE 계좌 projection은 기존 `project_account_target` 사용. 접수/부분접수/가상leg를
  확인체결로 바꾸지 않는다. 라이브 허가가 없거나 준비 미완료면 주문0.
- 실제장 종료/일요일 스모크는 provider연결 확인일 뿐 prospective ADD 성과가 아니다.
  배포·첫예정실행·수익성·LIVE준비를 각각 보고한다.

최소30종료/20진입일/10승자 및 비용10/25bps, 승자포착90%, 최고승자제거 조건은 유지한다.
상태: 최초 최대50% SHADOW 코드 검증 완료. LIVE 연결은 미완료다.
기본 운영 경로 유지, 새 cron/flag 변경 없음. 상세 증거는 `oneil-runtime-v1-validation.md`.
