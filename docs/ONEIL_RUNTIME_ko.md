# 적응형 SHADOW 실행 및 LIVE 전환 경계

2026-09-27. 사용자 확정: **최초 최대50%, 이후 조건부80/100%**.

## 현재 가능한 것

- `tools/run_oneil_shadow.py`: 실제 원본 캡처·현재 전략 보유DB·공개 시세·시장 상태를
  읽고 가상 매수를 원장에 적용하는 독립 실행기. 주문·메시지·계좌DB 쓰기 없음.
- 기본군 `INITIAL_POLICY_50`: 최초 캡처 때0% 대기, 유효한 최신 입력에서 최대50%
  진입. 조건 불충족이면 미진입, 비용 포함 위험 한도가 작으면50%보다 작게 진입.
- 다음 유효한 봉에서는 높은 적격 목표80/100으로 직접 확대. 실제 정책 평가기와
  기존 StrategyLedger 회계를 재사용한다. 같은 봉 정규/기계 평가로 중복 증액하지 않는다.
- 원본 손절의 하향 금지, 입력 결측과 독립적인 보호, 지연 도착한 원래 청산 반영.
  단, 이미 청산시각 이후 증액했다면 명시적 충돌로 거부하고 가격을 조작하지 않는다.
- 최초 입력·결정·가상 leg는 한 트랜잭션에 기록한다. 실행 시작 후 중단되어 완료
  기록이 없으면 다음 실행에서 알 수 있다. 원본 캡처/tape의 best-effort 한계를
  없앤 것은 아니므로 전체 수집 완전성이나 prospective 성과는 주장하지 않는다.

## 구동 방법

먼저 검증된 배포와 최초 원본 캡처가 필요하다. 다음 환경변수는 준비할 항목이며
이번 작업에서 운영 서버에 설정하지 않았다.

- `SCENARIO_SHADOW_CAPTURE_ENABLED`: 기존 최초 시나리오 캡처.
- `ONEIL_AUTO_REVIEW_CAPTURE_ENABLED`: 보고서 sidecar의 자동 setup 검토.
- `ONEIL_TAPE_CAPTURE_ENABLED`: 원래 전략 청산 연결. 실패 가능성은 계속 별도 표시.

```bash
python tools/run_oneil_shadow.py \
  --mode SHADOW \
  --capture-db runtime/scenario-shadow-capture.sqlite \
  --holdings-db stock_tracking_db.sqlite \
  --tape-db runtime/oneil-capture-tape.sqlite \
  --runtime-db runtime/oneil-initial50-shadow.sqlite \
  --since <검증된-원본수집-시작시각-ISO8601> \
  --max-slots <기존-전략의-슬롯한도> \
  --calendar AUTO --source mechanical --cycles 1
```

DB 경로는 실제 환경에 맞춰 확인한다. 입력DB는 읽기 전용이며 실행원장은 별도다.
같은 파일·심볼릭 링크·하드링크를 입력과 실행원장에 중복 지정할 수 없다.
한 계좌의 전체 보유 행을 읽어 슬롯 수와 정확한 decision/position 연결을 검증한다.
모드·최초진입군·시작경계·한도·입력경로 변경은 기존 원장에 소급 적용하지 않는다.
다른 구성은 새 전용 원장을 사용해야 한다. 이전10% 파일을 새50% 원장으로 쓰지 않는다.

`--cycles 390 --interval 60`은 같은 프로세스에서 최대390회 실행하며 이력 캐시를
재사용한다. 매 평가 종료 후60초 대기이므로 정확한 매분 시작을 보장하지 않는다.
최초 이력 준비는 더 오래 걸릴 수 있다. 실행파일은 새 cron을 설치하지 않는다.
정규 배치 평가도 `--source regular`로 같은 입력·정책 경로를 사용한다.
`--calendar AUTO`는 공급자가 확인한 거래소만 사용하며 추정 fallback은 없다.

중단 시 이 독립 실행기를 멈추면 신규 가상 증액만 멈춘다. 기존 실물 손절 루프와
운영 BUY/SELL은 바꾸지 않았고 이 실행기에 의존하지 않는다.

## 입력과 가상 체결의 의미

시세는 공급자의 `regularMarketTime`을 보존한다. 조회시간으로 덮어쓰지 않는다.
시장 국면은 기존 계산 함수와 MarketPulse를 완료된 지수 일봉으로 다시 계산한다.
GSPC200거래일과 내부 결측·중복을 검사한다. 공급자의 VIX 추가 휴일 행은 명시적으로
NYSE 거래일에 맞추고 제외 날짜와 원본 해시를 남긴다. VIX 거래일 누락은 허용하지 않는다.
동시간 거래량은 기존 정규장/직전20거래일 같은 구간 계산기를 사용한다.

기존 원장의 실제 적격 진입을 기준선100%로 기록하고, 새50군은 현재 입력에서 처음
확인된 관측가격에 진입한다. 평가 지연에 따른 가격 차이가 있으므로 순수 sizing 효과가
아니다. 가상 체결은 관측가격 가정이며 실제 호가·부분체결·시장충격 검증을 대신하지 않는다.
과거 원본을 가져왔다는 이유만으로 해당 기간을 전진 검증으로 바꾸지 않는다.

## LIVE 실행 연결과 승인 경계

2026-09-28 보완으로 다음 연결을 구현했다. 운영 실행기는
`tools/run_oneil_execution.py`, 공통 실행 원장은 `oneil_execution.py`다.

1. 기존 전액 최초 주문을 대체하는 적응형 최초 주문 라우팅.
2. 계좌·종목·캠페인의 원자적 실행 소유권.
3. 확인된 체결·부분체결·미체결을 수량/금액으로 대사하는 공급자.
4. 증액 금액 예약과 재시도·UNKNOWN 복구.
5. 추가매수와 청산의 경쟁 조정 및 미체결 매수 취소 확인.
6. 기존 ExecutionService로 전달하는 실제 브로커 연결.

기존 연구 함수 `project_live_candidate`는 저장된 결정과 실제 계좌 형식의 입력을 검증하고
기존 정수주 계산기로 수량을 **계산만** 한다. 그 입력은 아직 인증된 체결 공급자가
아니며 주문 권한은 생기지 않는다. 부분체결·예약·미확정·가상 체결·기존 전액 포지션
편입을 거부한다. 환경변수를 LIVE로 바꾸거나 계산이 성공해도 주문하지 않는다.

실제 `oneil_dispatcher`는 동일한 예약·대사 경로에서 SHADOW는 모의 체결을,
LIVE는 기존 ExecutionService/KIS 어댑터를 사용한다. 미확정 매수가 있어도 이미
확인된 소유 수량은 보호 매도하며, 미결 매수까지 해결되기 전에는 종료하지 않는다.
최초·증액·청산 요청은 같은 계좌/종목 소유권을 사용한다.

`readiness()`는 **기술적 전환 경로 구현**과 **LIVE 활성화 승인**을 구분한다.
LIVE에는 계좌·예산·초기50군·구현 해시·유효기간이 묶인 별도 승인 파일이 필요하다.
승인은 전략 행 생성 전, 주문 전, 마지막 시세 검증 때 재검사한다. 승인 만료/OFF는
신규 매수를 막지만 기존 포지션 보호를 중단하지 않는다. 향후 전환은 새50%군의
성과·운영 증거를 검토한 뒤 사용자의 명시적 LIVE 승인으로 새 캠페인부터 적용한다.
기존 가상 포지션을 실계좌 보유로 바꾸거나 기존100% 보유에 ADD를 붙이지 않는다.

## 파일

- `oneil_runtime_inputs.py`: 실제 읽기 전용 시세·시장·거래량·현재 gate 생산.
- `oneil_shadow_runner.py`: 원본/보유 연결, 실행 경계·중단 기록·공통 구동.
- `oneil_runtime.py`: CAS·멱등성·보호·최대50% 진입과 증액, 기존 회계 재사용.
- `oneil_live_boundary.py`: 실제 미구현 사항을 보여주는 잠금과 주문 없는 계좌 계산.
- `strategy_ledger.py`: 소유한 캠페인의 직접 target/sell/mark 우회 차단.

배포·첫 정규 실행·성과 상태는 별도 검증 기록을 참고한다.
